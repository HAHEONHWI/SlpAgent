# 기관 지식검색

`knowledge.search`는 `organization_id`로 조회하고 `needs_ocr`, `needs_review` 페이지를 건너뛴다. 응답에는 `document`, `page`, `text`가 포함된다. 검색 API의 자료 원문은 로그인한 기관 사용자에게만 반환한다.

`POST /ai/dialogue`는 현재 기관의 허가된 검수 완료 자료를 함께 검색해 최대 4개 발췌를 답변 근거로 제공한다. 답변에는 `[자료 N]` 인용과 문서명·페이지를 표시하고, 검색 실패 또는 결과 없음 상태를 구분한다. 검색된 자료는 도구 호출이 끝난 뒤 도구가 비활성화된 답변 단계에서만 모델에 전달한다. 원문과 메타데이터는 JSON으로 구분한 user 입력이며 system/developer 지시문에 붙이지 않는다.

## 언어치료 지식 Q&A와 임상 모드

새 대화의 기본 `mode`는 `knowledge`다. 수용·표현언어, 조음·음운, 어휘·의미, 구문·화용, 발달과 평가 원리를 설명한다. 자료 기반 답변과 일반 지식은 구분한다. 별도 모델 학습이나 검증된 규준 데이터 제공을 의미하지 않는다. 지식 모드에서는 아동 연결, 임상 기록 조회 도구 및 초안 생성 도구를 허용하지 않는다.

아동 기록이 필요한 경우 `mode=clinical`을 명시한다. 모드는 대화 생성 시 고정하고 기존 대화에 대한 모드 변경 요청은 거부한다. 이전 저장 대화에 mode 필드가 없으면 아동 연결 유무로 기존 임상/지식 모드를 복원한다. 초안 생성 도구는 현재 메시지의 `allow_drafts=true`, 선택 아동, 쓰기 권한을 모두 확인한 뒤 제공한다. 이 허가는 다음 질문에 유지되지 않는다. 기록 반영은 기존 치료사 승인 API에서 수행한다.

임상 모드에서 선택 아동의 최근 경과를 물으면 `get_recent_records`로 완료 회기·상담·승인 녹음 요약을 기록 날짜 최신순 최대 10건 조회한다. 승인된 회기 기록문을 포함하고 미승인 초안·녹취 원문은 제외한다. 매 조회 시 현재 기관과 담당 아동 권한을 확인하고 알려진 아동 이름·연락처를 마스킹한다. 검사·행동·어휘·활성 목표는 기존 읽기 도구로 상세 조회한다. 조회는 기록을 변경하지 않으며 지식 모드에서는 허용하지 않는다.

도구가 허용된 아동 연결 임상 요청은 서버가 매번 최근 기록을 먼저 조회하여 `untrusted_clinical_records` user 데이터로 전달한다. 모델이 행동 관찰 도구만 호출하더라도 상담·승인 녹음 기록을 빠뜨리지 않도록 한다. 기존 대화에 기록이 없다는 AI 답변이 남아 있어도 현재 조회 결과를 우선 사용한다. 첨부로 도구가 비활성화된 요청과 지식 모드에서는 자동 조회하지 않는다.

보호자 상담을 저장하면 `organization_id`·`child_id`가 지정된 `parent_consultations` 아동 이력으로 남고, 별도 이관 없이 다음 임상 대화의 최근 기록 조회에 반영된다. 직접 저장 API는 `session_summary`(수업 요약), `parent_concerns`(보호자 우려), `home_activities`(가정 활동)도 보존한다. AI는 상담의 보호자 보고와 치료사의 직접 관찰을 구분한다. 녹음 AI 초안은 기존 검토·승인 후 `recording_records`로 저장된 내용만 사용한다. 상담을 저장했다는 이유로 회기·검사·행동 기록을 추가 생성하지 않는다.

## 프롬프트 인젝션 방어

- JSON API는 mode·메시지·대화 ID·아동 ID·초안 허가만 받으며 role·instructions·tools 등 추가 필드를 거부한다.
- 직접적인 규칙 무시·시스템 프롬프트 공개 요청의 대표 패턴을 Unicode 정규화 후 차단한다. 이 패턴 검사는 보조 장치이며 모든 변형을 탐지하지는 못한다.
- 서버가 도구 목록과 실행 허용 목록을 결정한다. 모델의 함수 호출만으로 권한이 생기지 않으며 지식 모드에서는 함수 호출을 실행하지 않는다.
- 검색자료·파일·이미지·이전 답변은 낮은 권한의 데이터다. 임상 도구의 반환값과 최종 답변도 알려진 아동 이름·연락처 및 이메일·전화번호를 마스킹한다.
- Markdown의 HTML·외부 이미지와 모델 생성 외부 링크의 클릭 동작을 비활성화해 추적 이미지 로딩을 막는다.

시스템 지시의 우선순위, 요청별 도구 권한, 기관·아동 격리와 승인 절차를 함께 적용한다. 자유로운 자연어·시각 입력에서 모든 인젝션을 완전히 차단했다고 보장하지 않는다. 구조적 접근 차단은 fake model 공격 테스트로 검증하고, 실제 모델의 답변 품질·공격 저항성은 별도 운영 평가가 필요하다. 기준: [OpenAI Safety in building agents](https://developers.openai.com/api/docs/guides/agent-builder-safety).

AI 대화 첨부는 PDF, PNG, JPG, WEBP, TXT, MD, CSV, DOCX, HWP, HWPX를 지원한다. 파일은 최대 4개, 파일당 10MB, 전체 20MB이며, PDF는 40페이지까지 받는다. 텍스트·DOCX·HWP/HWPX에서 추출한 텍스트는 파일당 80,000자까지 전달한다. 원본 파일은 앱 대화 저장소에 저장하지 않고 첨부 이름·유형만 메시지에 저장한다. 파일을 보낼 때 사용자는 아동 식별 정보를 가명 처리했음을 확인해야 한다. 텍스트 추출물은 알려진 아동 이름·연락처와 이메일·전화번호를 마스킹한 뒤 OpenAI 요청에 포함한다. PDF와 이미지의 시각 정보는 자동 비식별화하지 않으므로 식별 정보가 없는지 사용자가 확인해야 한다. HWP/HWPX는 텍스트·표를 Markdown으로 추출하며 문서에 포함된 그림은 분석하지 않는다.

첨부와 검색 결과는 신뢰할 수 없는 참고 데이터로 취급한다. 첨부가 있는 요청에서는 AI 도구를 비활성화한다. AI가 제안하는 초기 임상 의견은 근거·강점·우려·대안 가설·한계·추가 평가 항목을 담는 치료사 검토용 초안이며, 확정 진단이나 자동 기록 변경으로 사용하지 않는다.

AI 도구에는 원문 `text`를 넣지 않는다. 도구 호출에는 문서명·페이지·검사 코드·문항 ID만 전달하며, 자료의 지시문은 데이터로만 취급한다. 원문이 필요한 사용자는 기관 내부 `/knowledge/search` API를 이용한다.

임베딩 벡터는 문서에 저장하고 cosine 점수는 Repo 인터페이스 뒤에서 기관별 결과에 대해 계산한다. 현재 Repo에는 벡터 검색 메서드가 없고 Firestore의 대규모 nearest-neighbor 검색을 직접 쓰지 않아 메모리 저장소와 테스트에서 같은 동작을 재현할 수 있다. 이 방식은 기관 문서 전체를 읽으므로 규모가 커지면 org 필터를 유지하는 벡터 어댑터로 교체해야 한다.

저작권 자료의 파생 텍스트가 원격 Firestore로 가는 ingest는 `--allow-reference-text-upload` 없이는 중단된다. OpenAI 임베딩은 `OPENAI_EMBEDDING_MODEL`과 `OPENAI_ALLOW_REFERENCE_EMBEDDING_UPLOAD=true`를 모두 설정해야 활성화된다. 기본 설정에서는 한국어 bigram 검색으로 폴백하고 원문을 외부 임베딩 API로 보내지 않는다. 활성화 전 사용 권한과 기관 정책을 확인한다.

텍스트 PDF 추출 JSON과 문항 ID 메타데이터를 기관 저장소로 가져오는 스크립트는 `cd backend && .venv/bin/python -m scripts.ingest_knowledge ORG_ID ../extracted --allow-reference-text-upload`다. 권리 검토 전에는 실행하지 않는다.
